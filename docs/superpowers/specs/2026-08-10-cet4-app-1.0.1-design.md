# CET-4 App 1.0.1 设计规格

日期：2026-08-10
状态：已获用户批准，待实施
版本：1.0.1+2

## 目标

面向已在 iPhone 13 上侧载运行的 CET-4 App，交付一个专注于学习闭环可靠性的 1.0.1 版本：

1. 修复单词发音无声的问题，采用设备本机英语 TTS。
2. 学习中标记“不认识”后，生词本无需重启即可显示新词。
3. 设置保存后立即影响学习、复习、生词本和统计页面。
4. 当日计划完成后，允许继续按批次学习额外新词。
5. 可从设置中浏览当前词书全部单词及释义。

本版本只调整客户端离线体验，不新增账号、网络服务、云端发音或词库内容。

## 技术边界

- Flutter 和现有 Material 3、Riverpod、Drift 架构保持不变。
- iOS 为主要交付和验证平台；代码保持 Android 兼容，但不将 Android 构建作为本次发布前置条件。
- 所有发音使用 `flutter_tts` 调用设备本地语音。默认优先 `en-US`，不请求或保存任何云端凭据。
- 所有设置和学习记录继续保存到本地 SQLite 数据库。
- 应用版本从 `1.0.0+1` 更新为 `1.0.1+2`；设置页显示 `1.0.1`。

## 架构与数据流

新增一个轻量的 Riverpod 数据变更协调层，作为已有 `StudyNotifier`、`NotebookNotifier` 和 `SettingsNotifier` 之间的同步机制。

- 学习状态发生变化时，学习模块写入数据库后发布学习数据已变化事件。
- 生词本发生变化时，发布生词本数据已变化事件。
- 设置保存或当前词书切换后，发布设置已变化事件。
- 页面或 Notifier 订阅其所需事件：生词本只重新加载列表；设置重新加载统计；学习页重载当天会话；复习模块按现有模式重新读取当前设置。

协调层不保存业务数据，不替代 Drift 数据库；它只确保由 `IndexedStack` 保活的隐藏 Tab 不会展示旧状态。每次数据库写入成功后才发布相应事件。失败时保留当前状态并向用户显示可理解的错误，不静默丢失写入失败。

## 发音

### TTS 服务

从学习页面提取单独的本机 TTS 服务，负责生命周期、平台配置和错误归一化：

1. 初始化 `FlutterTts`，注册开始、完成和错误回调。
2. 设置 `awaitSpeakCompletion(true)`、英语语速、音高和 `en-US` 语言。
3. 读取已安装语音列表，优先选择语言标识为 `en-US` 的声音；若该声音不可用，保留平台可用的英语语音并向用户给出提示。
4. iOS 上配置播放所需音频会话，使语音播放不会因默认会话策略而静默失败；应用进入后台时停止当前播放。
5. 每次播放前停止尚未完成的上一条发音，避免快速连点叠加。

### 用户体验与错误处理

- 发音按钮在服务准备前显示忙碌状态并阻止重复点击。
- 播放错误、未安装英语语音或初始化失败时，在学习页显示 Snackbar，说明失败原因和可采取的系统设置操作。
- 不吞掉 TTS 异常；诊断信息通过 `debugPrint` 记录，但不暴露底层堆栈给用户。
- 不增加在线真人发音回退，保证离线可用和无外部依赖。

## 生词本即时刷新

学习页将“不认识”写入 `progress` 和 `notebook` 后：

1. 写入成功后发布生词本变更事件。
2. `NotebookNotifier` 收到事件后按当前排序方式重新加载生词列表。
3. 当前轮学习完成时再次请求加载，覆盖后台 Tab 未显示期间发生的多个写入。
4. 手动星标或从生词本移除单词也发布同一类事件，确保数量和列表始终一致。

刷新不打断正在进行的生词本自测；若用户在自测模式，新的列表数据在回到列表模式后加载，避免题目会话在途中变化。

## 设置即时生效

### 保存语义

- 修改每日学习量后，数据库成功写入新值，再通知学习模块重新计算当天可学数量。
- 切换 CET-4/CET-6 后，数据库成功写入新词书，再通知学习、复习、生词本和统计模块刷新到新词书上下文。
- 修改提醒开关或时间后，先保存设置并完成通知调度/取消，再更新界面状态；失败时给出提示并保持一致的已保存状态。
- 重置当前词书后，刷新学习会话、生词本和设置统计。

### 学习会话处理

设置变化后的“立即生效”定义为：学习页丢弃尚未提交的当前卡片批次，并以最新词书和每日学习量从数据库重新创建当天会话。已点击“认识”或“不认识”且写入成功的单词记录保留，不会回滚或重复计入新词。

## 额外 10 词

当常规当日任务完成后，学习完成页展示 `再来 10 词` 操作。

- 每次点击从当前词书获取最多 10 个没有 `progress` 记录的新词，开始一轮独立学习批次。
- 操作可重复使用；每一轮均为最多 10 词，直至当前词书没有未学习单词。
- 额外批次不修改 `daily_quota` 设置，也不改变常规计划完成状态。
- 学习完成页展示当天实际新增学习总数，包含常规任务和全部额外批次。
- 当没有更多新词时，按钮禁用并显示“当前词书已无新词”。
- 加载失败时保留完成页，并显示重试提示。

## 词书浏览

### 入口与页面

在设置的“当前词书”区域提供“查看词书”入口。进入后打开只读词书浏览页，默认显示当前选中的 CET-4 或 CET-6 词书。

每一项展示：英文单词、词性（存在时）和中文释义（存在时）。浏览不改变学习进度、生词本或复习状态。

### 查询与性能

- 数据库增加按词书、英文或中文释义关键字查询的 API。
- 页面使用分页或增量加载，每次读取固定大小的数据块，避免一次渲染数千词。
- 搜索输入防抖后从第一页重新查询；清空搜索回到词书顺序。
- 空结果显示明确空状态；数据库读取错误显示重试操作。

## 数据库与兼容性

本版本不改变现有表结构。新增的是词书浏览查询 API 和可能的查询参数，不需要 Drift schema migration。既有预置数据库、用户进度、生词本和设置数据保持可用。

## 测试与验收

### 自动验证

- 为 TTS 服务选择语音、初始化失败和播放失败路径添加单元测试或可替换平台接口测试。
- 为学习状态新增额外批次、已无新词和设置变更后重载的行为添加 Provider 测试。
- 为生词本变更事件和词书查询分页/搜索添加数据库或 Provider 测试。
- 运行 `flutter analyze lib test`。
- 运行 `flutter test`。

### iPhone 13 手工验收

1. 点击单词发音可从设备扬声器或已连接音频设备听到英语读音；若设备没有可用英语语音，应用显示明确说明。
2. 标记“不认识”后切换到生词本，无需重启即可看到该词；结束一轮学习后列表仍完整同步。
3. 修改每日学习量或词书后返回学习页，当前内容立即按新设置更新。
4. 常规任务完成后可重复点击“再来 10 词”；每日学习总数正确累计。
5. 设置中可进入词书浏览，搜索英文或中文释义能找到对应条目，滚动加载稳定。

### 发布

1. 更新 `pubspec.yaml` 版本为 `1.0.1+2`。
2. 提交仅包含本版本相关源代码、测试、规格和版本信息的改动。
3. 推送至 GitHub `master`，触发现有 macOS GitHub Actions 工作流生成无签名 iOS IPA。
4. 验证工作流成功后，使用 Sideloadly 安装新 IPA 到 iPhone 13 进行上述手工验收。
